Tools and toolsets

The agent can only do what it has a tool for. Here is what you get out of the box, how toolsets are switched on and off and what to watch out for.

A tool is how the agent actually does something. Every model can talk — but writing a file, running a command, opening a website or querying a database only happens when the agent has a tool for it. A toolset is a bundle that is switched on and off as a whole.

Tools versus toolsets

The difference is like tools and a toolbox: a tool is one thing, a toolset is the box you take to a job. You decide which boxes the agent gets — and that also decides what it can do.

TermWhat it isExample
ToolOne specific ability with a fixed input and outputweb_search, read_file, terminal, delegate_task
ToolsetA group of tools switched on or off togetherweb, file, terminal, coding
Connection (MCP)An outside program that brings its own toolsa database, a company system, a third-party tool

What the agent can do out of the box

A fresh install comes with a broad set of tools. Grouped by area:

AreaExample toolsWhat for
Webweb_search, web_extractSearching and reading pages
Terminal and filesterminal, read_file, patch, processWorking on the server and in files
Browserbrowser_navigate, browser_snapshot, browser_execA real browser where clicking is needed

Get the exact list any time: hermes tools.

Switching toolsets on and off

When you want the agent to do only what you need, narrow the toolsets. Fewer tools means less room for mistakes and faster answers.

❯ hermes chat --toolsets "web,terminal" # only these two ❯ hermes chat --toolsets all # everything available ❯ hermes tools # overview and checkboxes

To make it permanent, edit the profile's config.yaml — either list the toolsets you allow, or list the ones you forbid:

# ~/.hermes/config.yaml enabled_toolsets: [web, file, terminal] disabled_toolsets: [browser] # the browser is not needed at all

Note: web_search is deliberately not part of the browser toolset, so disabling the browser does not take web search away from you.

When there are too many tools

With two hundred tools switched on, the model gets lost — every tool description takes up space that your request could use. Hermes solves this with tool search: only a handful of the most used tools stay out, the rest is fetched the moment the agent needs them.

When it happensWhat happens
There are many tools (typically over 30)Some tools move behind search; the agent asks for them by itself
Why it helpsAnswers are faster and cheaper, the model stays focused
When it is wrongWhen the agent does one narrow job over and over — then fewer toolsets with search off work better

In practice: when the agent reaches for a tool you did not expect, check whether it has more toolsets enabled than you need. Configure it with hermes tools — no hand-editing files.

Where tools run (terminal backends)

As long as the agent runs commands on your server, we call it the "local" backend. It can also run elsewhere — useful when you do not want to give it access to your own system, or when you need an environment your server does not have.

BackendWhen it fitsHow to set it
local (default)Your own server or VPS — simplest and fastestnothing to configure
remote machine over SSHWorking on another machine you already havecredentials in the backend settings
container (Docker)You want to separate what the agent may touch — it sees only the containerterminal.backend in config.yaml
cloud sandbox (Modal, Vercel Sandbox)You have no server and want it to live only for the jobterminal.backend plus credentials
❯ hermes config set terminal.backend modal ❯ hermes config set terminal.backend singularity

A container is not a security guarantee by itself: it only protects what the agent cannot reach into. Permissions and command approval are covered on the Security page.

Long jobs and administrator rights

SituationHow it works
A job runs long (backup, copying, watching a log)The agent starts it in the background and can do other work; it can check the status any time
A command needs sudoAn interactive session shows a masked password prompt (cached for that session). Passwords are never sent into a container or into chat
Passwordless sudoRuns with no prompt — nothing to fill in
The job runs in a subagentA password prompt cannot be opened there — run that command in the main conversation

Three pitfalls from our own running systems

What happenedHow to spot it and what to do
A tool reported success and nothing happened. The call went through, the output looked fine, the change was nowhereDo not ask the tool whether it did the job — verify the result somewhere else: in the file, with a database query, with the page's HTTP code. Write the verification into your request
A connected tool returned data from another project. The server answered correctly, but from the wrong database (we had two projects and one tool between them)For outside tools, verify what they are connected to and ask about a specific row you know. When it does not match, fix the connection, not the agent
Secrets showed up in the output as ***Hermes masks secrets in output. Never verify one by printing it — the print comes back empty or wrong even when the value is fine. Use it directly inside the command

Our tips

TipWhy
Enable only the toolsets you really useFewer tools mean faster, more accurate answers
Say how the work should be verified"The page must return 200" or "show me the row from the database" — then nothing can just be claimed
When the agent can do everything but nothing well, narrow the scopeA narrow toolset with a clear request beats a pile of tools
Test a new connection on something you knowOne simple query with an expected answer reveals a bad connection before you build on it
