Skill curator

The curator never deletes. The harshest thing it does is archive — and that is one command away from coming back. It solves one annoying fact: when the agent saves a new skill for every novel problem, half a year later the library is full of narrow near-duplicates. The curator keeps that in check, but leaves the decisions to you — and it does not touch the library before you have had a chance to look.

What the curator does

It tracks how often each skill was viewed, used and patched, and moves it through three states: active → stale → archived. With the consolidation phase enabled it occasionally runs a short review on a cheaper model that proposes merges or patches drift.

PhaseWhat it doesDoes it cost money?
Automatic transitionsUnused for 14 days = stale; 30 days = archivedNo (always on while the curator is enabled)
LLM consolidationSurveys the skills, proposes merging near-duplicates and fixes drifted textYes, but it can run on a cheap model

Only agent-created skills are managed automatically. Skills installed from the hub (agentskills.io) are always off-limits.

When it runs

Not on a cron schedule, but on inactivity. Hermes checks at CLI start, during gateway housekeeping (which also covers a local Desktop, since it attaches to the gateway) and on the hourly hermes serve/dashboard timer whether both are true:

ConditionDefault
Time since the last runinterval_hours = 168 (7 days)
The agent has been idle long enoughmin_idle_hours = 2 hours

The first run is deferred by a full interval: on a fresh install it just records “now” and the first real pass happens a week later. That is deliberate — you get time to review the library and pin anything important.

Configuration

curator: enabled: true interval_hours: 168 # 7 days min_idle_hours: 2 stale_after_days: 14 archive_after_days: 30 consolidate: false # LLM consolidation — off prune_builtins: false # also archive unused bundled skills
KeyPurpose
consolidateEnables the consolidation pass. It is the only phase that rewrites skill content — which is why Hermes snapshots the library before it
prune_builtinsArchive unused bundled skills too. Optional, because bundled skills disappearing looks like a broken install
auxiliary.curatorWhich model runs the review. Leave auto (main model) or pin a cheap one
# cheaper model for the review (config.yaml) auxiliary: curator: provider: openrouter model: google/gemini-3-flash-preview timeout: 600

Commands worth knowing

CommandWhat it does
hermes curator statusLast run, counts, pinned skills, least-used skills
hermes curator run --dry-runStart here — prints what the curator would do and changes nothing
hermes curator runRuns a pass now (prune-only unless consolidation is on)
hermes curator pin <skill>Never auto-transition or archive this skill
hermes curator backup / rollbackManual snapshot of the library and returning to it
hermes curator restore <skill>Moves an archived skill back to active
hermes curator ledgerWho changed what and when; rollback <id> undoes one change

What never happens

WorryReality
“It will delete my skills”It does not delete. Archiving moves a skill to ~/.hermes/skills/.archive/
“It will touch hub skills”No, those are always excluded
“It will archive a skill a cron job uses”No. A skill referenced by any scheduled job (even a paused one) is treated as pinned
“It will drop a skill nobody used yet”No. A skill with zero uses gets a grace period — it is not archived before it is as old as stale_after_days

How we do it

HabitWhy
run --dry-run first, then clean up by handWith a library that grew over months it is better to see the proposal and decide yourself
Turn consolidation on only after the first passClean up first, merge afterwards — otherwise you merge skills that merely share a name
Keep skills in gitVersions, diffs and rollback without relying on the curator's snapshot
Archive, never deleteMonths later a “useless” skill turns out to hold one recipe you need

Common mistakes

SymptomCause and fix
The curator never runsBoth conditions must hold: the interval has passed and the agent is idle. On a fresh install the first run waits a full interval
Something is missing after consolidationhermes curator rollback --list and restore a specific snapshot; the ledger also records the pre-merge content
Bundled skills are disappearingYou have prune_builtins: true — turn it off and bring archived skills back with restore
The review is expensivePoint auxiliary.curator at a cheap model; the archival pass itself costs nothing
