Agent s přístupem k repozitáři není „jen čtenář“ — má stejná práva jako vy. Když mu dáte token s právem zápisu, může pushovat, mazat větve i zavírat pull requesty. Začněte právem jen pro čtení, pusťte ho do jednoho repozitáře a teprve pak přidávejte práva podle toho, co mu opravdu chcete dovolit.

Co k tomu patří

VěcK čemu
GitHub CLI ghPřes něj agent dělá všechno — PR, issues, revize, repozitáře
Přihlášení gh auth loginBuď interaktivně, nebo tokenem (GH_TOKEN v prostředí)
Běžící bránaBez ní nefungují pravidelné úlohy ani webhooky
Skill githubHotový návod, jak s gh pracovat (je součástí Hermese)

Ověření, že to funguje

gh auth status # kdo jsem a co smím gh pr list --repo vlasnik/repo --state open --limit 3 gh pr diff 42 --repo vlasnik/repo # co PR mění

Když tohle projde, agent má přístup a můžete mu zadávat práci. Když ne, chyba obvykle říká, které oprávnění (scope) chybí.

Revize pull requestu

Zkontroluj tento pull request: přečti diff a najdi chyby, bezpečnostní problémy a nekvalitní kód. Buď konkrétní — čísla řádků a citace problematického kódu.

Agent si diff stáhne, projde ho a napíše strukturovanou revizi. Když chcete, aby to dělal pořád stejně, udělejte z toho skill (vlastní pravidla revize) — pak se nemusí pokaždé učit, co vás zajímá.

Cron je bezpečnější začátek: nic nevystavujete do internetu a přesto máte revizi u každého PR. Webhook přidejte, až když vám zpoždění vadí (viz stránka o webhookách).

SituaceCo s tím
