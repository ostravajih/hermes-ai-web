Přechod není kopírování složky — je to rozhodnutí, co si nechat. Hermes převezme z Claude Code, Codex CLI i OpenClaw to, co dává smysl (pravidla, paměť, skilly, MCP servery), a tajné klíče záměrně nechá doma. Vždycky vám ale nejdřív ukáže plán a teprve pak se ptá, jestli ho má provést.

Ze Claude Code a Codex CLI

hermes import-agent # samo najde ~/.claude nebo ~/.codex hermes import-agent claude-code # jen Claude Code hermes import-agent codex # jen Codex CLI hermes import-agent claude-code --dry-run # jen náhled, nic nezapíše hermes import-agent codex --source /cesta/.codex # jiné umístění hermes import-agent claude-code --overwrite --yes # přepsat konflikty bez dotazů

Pravidla typu Bash(npm run test:*) se převádějí na vzory (npm run test*). Pravidla, která se týkají nástrojů specifických pro Claude (např. Read(...)), import vypíše jako nepřevedená — nemá je na co namapovat.

Co se nikdy nepřevezme

CoProč
Soubory s přihlášením (~/.claude/.credentials.json, ~/.codex/auth.json)Import je vůbec nečte
Hodnoty vypadající jako tajemství v MCP serverechProměnné jako *_TOKEN, *_API_KEY a hlavičky Authorization se odstraní a vypíšou, abyste je doplnili vědomě

Přihlášení k modelům pak nastavíte přes hermes setup, klíče doplníte do ~/.hermes/.env. Je to otrava, ale je to jediný způsob, jak import nemůže omylem vysypat klíče tam, kde nemají být.

Jak se to chová

VlastnostVýznam
Nejdřív náhledPříkaz vždy vypíše plán po položkách; v neinteraktivním režimu skončí u náhledu, dokud nepřidáte --yes
Slučuje, nepřepisujeZáznamy paměti se odduplikují proti tomu, co už máte; allowlist a denylist se slévají s existujícím nastavením
Konflikty přeskočíMCP server nebo skill, který už v Hermesu je, se ohlásí jako konflikt a nechá být (přepíše jen --overwrite)

Z OpenClaw

hermes claw migrate # náhled, pak potvrzení hermes claw migrate --dry-run # jen náhled hermes claw migrate --preset full --migrate-secrets --yes # včetně klíčů, bez dotazů
CoKam
Osobnost (workspace/SOUL.md)~/.hermes/SOUL.md
Pokyny k pracovní složce (AGENTS.md)AGENTS.md v cíli (--workspace-target)
Dlouhodobá paměť a profilmemories/MEMORY.md a USER.md (sloučené, odduplikované)
Denní poznámkySloučí se do hlavní paměti
Skilly, MCP servery, nastavení modelůOdpovídající části config.yaml a skills/
PřepínačK čemu
--preset full / user-dataVše nebo jen uživatelská data bez infrastruktury
--migrate-secretsPřevzít i API klíče. Ani full je nebere samo — musí se říct výslovně
--skill-conflict skip|overwrite|renameCo se stejným jménem skillu (výchozí je přeskočit)
--no-backupPřeskočit zálohu ~/.hermes/, která se jinak dělá před zápisem (~/.hermes/backups/pre-migration-*.zip)

Ta záloha před migrací je vaše záchranná síť a obnovuje se přes hermes import. Nevypínejte ji, dokud nemáte jistotu, že migrace sedla.

Na co si dát pozor

SituaceCo s tím
Agent po importu „nezná“ vaše pravidlaPokyny z jiného nástroje skončily v paměti, ne v AGENTS.md projektu — pravidla k projektu patří do souboru projektu
Agent toho umí víc, než chceteAllowlist z Claude Code může být široký; projděte command_allowlist a uberte
MCP server se nepřipojilByl to konflikt, nebo mu chybí tajemství, které import záměrně odstranil
Chybí pravidelné úlohyCron se migrací nepřenáší — pravidelné úlohy založte znovu v Hermesu
Po měsíci se zdroje rozešlyImport je jednorázový. Buď ho spusťte znovu, nebo (lépe) přestaňte používat dva agenty na totéž

Doporučený postup

1) hermes import-agent --dry-run # co by se převzalo 2) projít plán a vypnout, co nechci 3) hermes import-agent # provést 4) hermes setup # přihlášení k modelům 5) doplnit klíče do ~/.hermes/.env 6) zkusit reálný úkol a porovnat se starým agentem
